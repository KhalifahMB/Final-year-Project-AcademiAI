### C1 - RLS Bypass Risk ⚠️ ARCHITECTURAL

**Status:** ⬜ OPEN (Requires Ops/Infrastructure Change)

**Problem:**
Database runtime user is a PostgreSQL superuser with `BYPASSRLS` attribute. The `academiai_app` role exists but is never used for actual connections.

**Impact:**

- Multi-tenant Row-Level Security is DECORATIVE
- Any app-layer bug can leak cross-tenant data
- No database-level enforcement of tenant isolation

**Action Steps:**

1. **In production, connect as `academiai_app` role**
2. **Verify role has NOBYPASSRLS:**
   ```sql
   SELECT rolbypassrls FROM pg_roles WHERE rolname = 'academiai_app';
   ```
3. **Re-own tables to academiai_app:**
   ```sql
   REASSIGN OWNED BY postgres TO academiai_app;
   ```
4. **Test RLS enforcement:**
   ```sql
   SET app.current_tenant_id = '<some-tenant-uuid>';
   SELECT COUNT(*) FROM resources; -- Should only see that tenant's data
   ```

**Risk Level:** HIGH - This undermines your entire multi-tenant architecture

---

### C2 - JWT in localStorage ⚠️ ARCHITECTURAL

**Status:** ⏳ DOCUMENTED (Requires Refactor)

**Problem:**
Both access and refresh tokens stored in `localStorage`, which is XSS-readable.

**Impact:**

- Any XSS vulnerability = complete account takeover
- Attacker can steal tokens via `localStorage.getItem('access_token')`

**Action Steps:**

1. **Move access token to memory** (React state/context only)
2. **Move refresh token to HttpOnly cookie:**
   ```python
   # Backend: Set cookie on login
   response.set_cookie('refresh_token', refresh, httponly=True, secure=True, samesite='Strict')
   ```
3. **Create cookie-based refresh endpoint:**
   ```python
   # Read from request.COOKIES['refresh_token']
   ```
4. **Update frontend to use in-memory access token**

**Risk Level:** HIGH - Common attack vector

## 💡 CODE QUALITY PATTERNS ESTABLISHED

### Standards to Follow:

**1. Async Operations:**

```javascript
// ✅ CORRECT: Use useMutation
const myMutation = useMutation({
  mutationFn: (data) => api.post('/endpoint/', data),
  onSuccess: () => {
    toast.success('Success!');
    qc.invalidateQueries({ queryKey: ['key'] });
  },
  onError: (err) => {
    toast.error(err.response?.data?.detail || 'Failed');
  },
});

// ❌ WRONG: Plain async function
const myFunction = async () => {
  try {
    await api.post('/endpoint/', data);
    toast.success('Success!');
  } catch (err) {
    toast.error('Failed');
  }
};
```

**2. Loading States:**

```javascript
// ✅ CORRECT: Show loading feedback
<Button disabled={mutation.isPending} onClick={() => mutation.mutate()}>
  {mutation.isPending ? (
    <><Loader2 className="mr-2 h-4 w-4 animate-spin" />Saving…</>
  ) : (
    'Save'
  )}
</Button>

// ❌ WRONG: No loading feedback
<Button onClick={handleClick}>Save</Button>
```

**3. Destructive Actions:**

```javascript
// ✅ CORRECT: Confirmation dialog
<AlertDialog open={!!confirmDelete} onOpenChange={setConfirmDelete}>
  <AlertDialogContent>
    <AlertDialogTitle>Are you sure?</AlertDialogTitle>
    <AlertDialogDescription>This cannot be undone.</AlertDialogDescription>
    <AlertDialogFooter>
      <AlertDialogCancel>Cancel</AlertDialogCancel>
      <AlertDialogAction onClick={handleDelete}>Delete</AlertDialogAction>
    </AlertDialogFooter>
  </AlertDialogContent>
</AlertDialog>

// ❌ WRONG: Immediate delete
<Button onClick={() => deleteMutation.mutate(id)}>Delete</Button>
```

**4. Cache Invalidation:**

```javascript
// ✅ CORRECT: Invalidate after mutation
onSuccess: () => {
  qc.invalidateQueries({ queryKey: ['resources'] });
  qc.invalidateQueries({ queryKey: ['bookmarks'] });
},

// ❌ WRONG: No cache invalidation
onSuccess: () => {
  toast.success('Saved!');
},
```
